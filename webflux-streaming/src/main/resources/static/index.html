WebFlux: adi request-lərdən fərqi

Netty üzərində, hər CPU nüvəsinə bir "event loop" thread-i. Thread gözləmir, işlər hadisə gələndə davam edir.

1. Thread modeli: 100 paralel sorğu

Hər sorğu 300 ms "gözləyir". Eyni gözləmə üç cür yazılıb. Server özü WebClient ilə 100 paralel sorğu göndərir (brauzer bir hosta cəmi ~6 əlaqə açır).

üsulümumi vaxtevent-loop thread-ləri

2. Üç servisə müraciət: ardıcıl və paralel (Mono.zip)

İstifadəçi (300 ms), sifarişlər (500 ms), tövsiyələr (400 ms). Paralel variant əlavə thread yaratmır.

3. Chat cavabı: SSE (Flux<ServerSentEvent>)

MVC modulundakı ilə eyni nəticə, amma nə executor, nə emitter, nə də "client hələ burdadırmı" yoxlaması var.

4. Eyni Flux<Order>, iki format

Bir controller metodu; formatı Accept header-i seçir. "Dayandır" basanda server də dayanır (backpressure + cancel), statistikaya baxın.
